# Phase 1 — Requirements Compliance Report
## Result: NON-COMPLIANT
### Summary
The committed code implements the required product search, category filter, price-range filter, combined filters, and single-product endpoint, and it satisfies most acceptance criteria (JSON responses, case-insensitive search, combinable filters). However, the commit removed checks for non-finite numeric inputs (NaN/Infinity) when parsing minPrice/maxPrice which can lead to surprising behavior and does not return a 4xx for those inputs.
### Missing requirements
- Validation for non-finite numeric values (NaN and Infinity) for minPrice and maxPrice — these should be treated as invalid input and return a 4xx error.
### Errors found
- techshop_testing/Server.py: import math was removed in the change shown in diff hunk @@ -2,7 +2,7@@. The subsequent numeric validation that used math.isnan/math.isinf was also removed.
- techshop_testing/Server.py: In diff hunk @@ -135,29 +135,25@@ the explicit checks for math.isnan() / math.isinf() during minPrice and maxPrice parsing were removed. As a result float('NaN') and float('Infinity') are accepted and not flagged as invalid; comparisons with NaN yield false and may silently filter out products instead of returning a 4xx error.
### Suggestions
- Restore non-finite number validation: re-add import math at the top of techshop_testing/Server.py (restore the removed line).
- When parsing minPrice and maxPrice (around the code changed in diff hunk @@ -135,29 +135,25@@), after converting to float, add checks like:
  if math.isnan(min_price) or math.isinf(min_price):
      return jsonify({"error": "minPrice must be a number"}), 400
and similarly for max_price. This ensures 'NaN' and 'Infinity' are treated as invalid inputs and produce a 400 response consistent with the intent to return 4xx for invalid inputs.
- Optionally, add tests that assert providing minPrice=NaN or maxPrice=Infinity returns 400 to prevent regressions.
### Quality notes
- Overall code is clear and organized: route handlers are straightforward, use of jsonify ensures JSON responses, and the filters are applied in a clear order (category → search → price).
- Search semantics are implemented as a case-insensitive substring match which matches the requirement as written.
- Category handling lowercases the input and accepts 'all' as a no-op filter — a reasonable convenience (not required by spec but harmless).
- Error messages are consistent and helpful (e.g., 'Invalid category', 'minPrice cannot be greater than maxPrice'), and appropriate 4xx codes are used for invalid input and missing resources.
- There are two @app.after_request handlers (set_session_cookie and add_cors_headers). Flask supports multiple after_request handlers, but be mindful of ordering if future handlers depend on response headers set by others.
