# Phase 1 — Requirements Compliance Report
## Result: NON-COMPLIANT
### Summary
Most requirements for product search, price filtering, combined filters, and single-product retrieval are implemented correctly (case-insensitive search, inclusive price range, combined filtering, JSON responses and correct 4xx/404 behaviour). However REQ-02 (category validation) is not strictly implemented: the server treats the category value "all" as a special valid value instead of rejecting it as an invalid category per the spec.
### Missing requirements
- REQ-02 strict validation: the requirements state the only valid categories are 'electronics' and 'accessories' and that an invalid category should produce a 400. The implementation accepts the category value 'all' and treats it as a bypass instead of returning 400.
### Errors found
- techshop_testing/Server.py: In get_products(), category validation treats 'all' as an allowed value rather than treating it as invalid. See the block added around the category check (git diff hunk starting at about line 114):
  if category:
      category = category.lower()
      if category != "all" and category not in VALID_CATEGORIES:
          return jsonify({"error": "Invalid category"}), 400
  This allows '?category=all' to be accepted rather than returning 400 as the requirements imply.
- Minor: techshop_testing/Server.py: There is no explicit handling for NaN / +/-Inf in price parsing. The original diff removed math imports and the NaN checks. Although the requirements do not explicitly require NaN/Inf handling, an attacker or malformed input like 'minPrice=NaN' could be parsed as float('nan') and comparisons behave unexpectedly. The price parsing code currently does:
  min_price = float(min_price_raw)
  (and similarly for max_price)
  without checks for math.isnan or math.isinf.
### Suggestions
- For REQ-02 strict compliance: remove the special-case acceptance of 'all' so that only the listed valid categories are accepted. Replace the category validation block in techshop_testing/Server.py (get_products) with:
  if category:
      category = category.lower()
      if category not in VALID_CATEGORIES:
          return jsonify({"error": "Invalid category"}), 400
  This will cause '?category=all' to return 400, matching the requirement that only 'electronics' and 'accessories' are valid.
- If you intentionally want to support 'all', update the requirements to mention that 'all' is accepted as a category that returns all products. Otherwise, to be robust against special float values, reintroduce checks for NaN/Infinity when parsing minPrice and maxPrice. For example (in techshop_testing/Server.py):
  import math
  ...
  min_price = float(min_price_raw)
  if math.isnan(min_price) or math.isinf(min_price):
      raise ValueError
  (handle similarly for max_price)
  This will ensure inputs like 'NaN' are rejected with a 400 and an informative message (e.g. "minPrice must be a number").
### Quality notes
- The implementation correctly applies filters in sequence on a working copy of PRODUCTS (filtered = list(PRODUCTS)), so combined filtering works as required.
- Search behavior is implemented in a clear and correct way: it is case-insensitive and treats empty/whitespace-only search terms as no-op (returns all products).
- Informative error messages and appropriate 4xx/404 status codes are used for invalid category, invalid price inputs, minPrice > maxPrice, and missing products.
- Code is generally readable and well structured. Minor issues to consider: two @app.after_request decorated functions exist (set_session_cookie and add_cors_headers) — Flask allows multiple after_request handlers, but keep this intention in mind. Also, re-adding explicit NaN/Infinity checks (see suggestions) would improve robustness.
- Other endpoints (cart, auth, checkout) are implemented in a straightforward manner but are outside the scope of this validation.
