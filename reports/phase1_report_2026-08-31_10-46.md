# Phase 1 — Requirements Compliance Report
## Result: NON-COMPLIANT
### Summary
The committed changes in techshop_testing/Server.py partially validate inputs (category and numeric parse) but do not implement several required behaviors: search-by-name is not applied, price-range filtering is not applied to results, and whitespace/empty search handling is missing. There is also a potential robustness issue for NaN/Infinity values and a minor mismatch vs. requirements around the allowed category token 'all'.
### Missing requirements
- REQ-01: Case-insensitive search filter is not applied to the product list (search handling is missing).
- REQ-01: Handling empty or whitespace-only search term that should return all products is not implemented.
- REQ-03: Applying minPrice/maxPrice filters to the returned products (inclusive) is not implemented.
- REQ-04: Combined filters (search + category + price) cannot work because search/price filters are missing from the filtering pipeline.
### Errors found
- techshop_testing/Server.py: In get_products(): the variable 'search' is read from request.args but no filtering by name is performed (see diff chunk starting at @@ -114,20 +114,20 @@ where 'search = request.args.get("search")' is set but never used).
- techshop_testing/Server.py: Price parsing code (diff chunk @@ -135,29 +135,25 @@) converts minPrice/maxPrice to float but never applies the parsed min_price/max_price to filter 'filtered'. The code only sets 'filtered = list(PRODUCTS)' and then filters by category; there is no subsequent list comprehension to filter by price.
- techshop_testing/Server.py: The requirements require that an empty or whitespace-only search returns all products; the commit does not trim or check search for whitespace- only strings and therefore will treat 'search="   "' as a search term rather than 'all'. (search trimming/empty-check is missing.)
- techshop_testing/Server.py: The import math was removed at the top of the file, and the prior checks for NaN/Infinity were removed. As a result, inputs like 'NaN' or 'Infinity' will be parsed to float('nan')/float('inf') and may silently bypass numeric validation and comparisons (diff shows removal of math import and removal of math.isnan/math.isinf checks in the min/max parsing blocks).
- techshop_testing/Server.py: The code accepts a special category token 'all' (it checks `if category != "all" and ...`) even though the requirements only list valid categories as 'electronics' and 'accessories'. This is a behavior mismatch (it may be acceptable, but it is not documented in requirements).
### Suggestions
- Implement search filtering (REQ-01): after reading search, do something like:
- if search is None or search.strip() == "": leave results unchanged (return all products)
- else: term = search.strip().lower(); filtered = [p for p in filtered if term in p['name'].lower()]
Place this filter after you create 'filtered = list(PRODUCTS)' and before/after category filtering so combined filters work.
- Apply price filters (REQ-03): after parsing min_price and max_price, filter products inclusive of endpoints:
- filtered = [p for p in filtered if (min_price is None or p['price'] >= min_price) and (max_price is None or p['price'] <= max_price)]
Add this after the category and search filters so combined filters (REQ-04) produce expected results.
- Restore robust numeric checks: re-add 'import math' and ensure you reject NaN/Infinity explicitly when parsing parameters. For example, after float conversion check `if not math.isfinite(value): raise ValueError` so inputs like 'NaN' or 'Infinity' return 400 (matching acceptance criteria about invalid inputs).
- Implement whitespace handling for search: treat search strings that are empty after stripping as if the parameter was not provided (return all products). Example: `if search is not None and search.strip() == "": search = None` or simply check search.strip() before applying filter.
- Resolve category behavior: either remove the 'all' special-case (require only 'electronics' or 'accessories' per requirements) or explicitly document and test the new 'all' behavior. If you keep 'all', ensure tests cover it. The easier fix to match requirements is to delete the 'category != "all"' condition.
- Add unit tests for: case-insensitive search, whitespace search, invalid category (400), numeric parse errors (non-number, NaN, Infinity), minPrice > maxPrice, inclusive price bounds, and combined filters (search+category+price).
