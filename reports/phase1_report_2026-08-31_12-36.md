# Phase 1 — Requirements Compliance Report
## Result: NON-COMPLIANT
### Summary
The committed code implements the functional requirements for product search, category filtering, price-range filtering, combined filters, and single-product retrieval, but contains a critical indentation bug that will cause a runtime/SyntaxError and prevent the server from running. There are also a couple of small robustness suggestions (e.g. strip whitespace on category).
### Errors found
- Indentation error in techshop_testing/Server.py inside get_products(): the newly added raised ValueError lines are mis-indented and will cause a SyntaxError / IndentationError at runtime. See git diff additions around the get_products() block (hunk starting at line ~138):
  +            if math.isnan(min_price) or math.isinf(min_price):
  +             raise ValueError
  and similarly for max_price:
  +            if math.isnan(max_price) or math.isinf(max_price):
  +             raise ValueError
  These 'raise ValueError' lines are not indented consistently with the 'if' block and must be fixed.
- Category handling does not strip surrounding whitespace before validation. In techshop_testing/Server.py get_products(), category is lowercased but not stripped (line where category is normalized). A query like ?category=%20electronics (leading space) would be treated as invalid and return 400 even though it reasonably should be accepted.
### Suggestions
- Fix the indentation so the raise is inside the 'if' block. Replace the problematic blocks in techshop_testing/Server.py with either of these correct forms (both minPrice and maxPrice):
  try:
      min_price = float(min_price_raw)
      if math.isnan(min_price) or math.isinf(min_price):
          raise ValueError
  except ValueError:
      return jsonify({"error": "minPrice must be a number"}), 400

  Or more succinctly use math.isfinite():
  try:
      min_price = float(min_price_raw)
      if not math.isfinite(min_price):
          raise ValueError
  except ValueError:
      return jsonify({"error": "minPrice must be a number"}), 400

  Apply the same fix for max_price with the corresponding error message.
- Trim whitespace from the category parameter before validation and lowercasing. Change the normalization in techshop_testing/Server.py get_products() from:
  if category:
      category = category.lower()
to:
  if category:
      category = category.strip().lower()
This will accept ' electronics ' as 'electronics' and avoid unnecessary 400 responses.
- Optional: Add unit or integration tests that exercise edge cases: empty search (""), whitespace-only search ("  "), category with extra whitespace and different casing, minPrice/maxPrice with NaN/Infinity strings, minPrice > maxPrice, and combined filters such as ?search=keyboard&category=electronics&maxPrice=150 to ensure REQ-04 is satisfied in practice.
- Optional: Consider using math.isfinite(value) which checks both NaN and +/-Inf in one call for clarity and fewer lines.
### Quality notes
- Positive: The implementation otherwise follows the requirements closely: search is case-insensitive and treats whitespace-only search as no filter; category validation returns the required 400 with the expected error body; price-range filtering is inclusive; combined filters are applied sequentially and will compose correctly; single-product endpoint returns 404 with the correct error body. All endpoints use jsonify() to return JSON.
- The code added handling for NaN/Infinity which is good defensive programming (though the indentation bug negates this until fixed).
- Minor design note: the code accepts a special 'all' category to bypass category filtering (not mentioned in requirements) — this is harmless but should be documented or tested if intended.
- There are two @app.after_request handlers (set_session_cookie and add_cors_headers). Flask allows multiple after_request functions, but consider combining them or documenting order if order matters.
- Formatting: returning the cart total as a formatted string (f"{total:.2f}") is fine for UI display but if API consumers expect numeric totals you may want to return a number instead.
